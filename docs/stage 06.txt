STAGE 06
DATA ENTRY & SUBMISSION WORKFLOW
Hospital Health Data Management, Reporting and Analysis System

============================================================
1. STAGE PURPOSE
============================================================

Stage 06 implements the operational data-entry and submission
workflow using the configuration created in Stage 05.

The purpose is to allow DATA_ENTRY users to:

1. View available active datasets.
2. View OPEN reporting periods.
3. Start a submission for a Dataset + Reporting Period.
4. Enter indicator values.
5. Save incomplete work as DRAFT.
6. Continue editing an existing DRAFT.
7. Validate entered values.
8. Submit the completed submission.
9. View their own submission status/history.

This stage creates the foundation required for Stage 07,
which will implement Reporting review, RETURNED, UNDER_REVIEW
and APPROVED workflow.

6. ONE ACTIVE SUBMISSION RULE
============================================================

There must be only one active submission for:

Dataset + Reporting Period

Therefore:

Dataset A + January 2026
= one submission

Dataset A + February 2026
= another submission

Dataset B + January 2026
= another submission

Do not create duplicate active submissions for the same
Dataset + Reporting Period.

The existing database uniqueness rule must be respected.

If a DATA_ENTRY user attempts to create a submission that
already exists:

Return a clear conflict response such as HTTP 409.

Do not create another submission.

============================================================
10. ACTIVE DATASET RULE
============================================================

Only ACTIVE datasets may be used for creating a new submission.

INACTIVE dataset:

- cannot create a new submission

Existing historical submissions for an inactive dataset remain
accessible according to their existing ownership/access rules.

Stage 06 must not delete historical data when a dataset is
deactivated.


============================================================
11. ACTIVE INDICATOR RULE
============================================================

When a submission form is opened:

Only ACTIVE indicators belonging to the selected dataset
should be presented for new data entry.

Inactive indicators must not be presented as new fields.

Historical data values for inactive indicators must remain
stored.

Do not delete historical indicator values.


============================================================
12. REPORTING PERIOD RULE
============================================================

Only OPEN reporting periods may be used for:

- creating new submissions
- editing DRAFT submissions
- submitting submissions

CLOSED period:

- cannot create new submission
- cannot edit DRAFT
- cannot submit DRAFT

If a period becomes CLOSED while a draft exists:

The draft becomes read-only.

The system must clearly communicate that the reporting period
is closed.

Do not allow the frontend alone to enforce this rule.

The backend must enforce it.

14. CREATE SUBMISSION LOGIC
============================================================

When DATA_ENTRY starts a submission:

1. Authenticate user.
2. Verify role = DATA_ENTRY.
3. Verify dataset exists.
4. Verify dataset is ACTIVE.
5. Verify reporting period exists.
6. Verify reporting period is OPEN.
7. Check whether Dataset + Reporting Period already has
   an active submission.
8. If duplicate:
   return HTTP 409.
9. Otherwise create submission.
10. Owner must be the authenticated DATA_ENTRY user.
11. Initial status = DRAFT.
12. Record created_at/updated_at correctly.
13. Return the created submission.

============================================================
19. SUBMISSION VALIDATION
============================================================

When DATA_ENTRY clicks Submit:

The backend must validate the complete submission.

Validation must include:

1. Submission exists.
2. User owns submission.
3. Submission status is DRAFT or RETURNED.
4. Dataset is valid.
5. Reporting period is valid.
6. Reporting period is OPEN.
7. All required ACTIVE indicators have values.
8. Values match indicator data type.
9. Minimum values are respected.
10. Maximum values are respected.
11. Decimal precision is respected.
12. Percentage rules are respected.
13. No unauthorized indicator is submitted.
14. No duplicate indicator value exists within submission.

If validation succeeds:

status = SUBMITTED

If validation fails:

status remains DRAFT or RETURNED.

Return clear validation errors.
