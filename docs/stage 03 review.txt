============================================================
5. DATABASE TECHNOLOGY / LIBRARY SELECTED
============================================================

Selected: Knex.js (knex) + mysql2 driver.

Rationale: single controlled migration solution, parameterized
queries, MySQL support, transaction support, maintainable, and no
heavy ORM overhead. Prisma/Sequelize/multiple ORMs were not used.

============================================================
6. DATABASE SCHEMA
============================================================

Single migration: server/migrations/001_core_schema.js.

============================================================
7. TABLES CREATED
============================================================

- roles
- users
- datasets
- indicators
- reporting_periods
- submissions
- data_values
- submission_history
- submission_amendments
- notifications
- audit_logs

============================================================
8. RELATIONSHIPS
============================================================

- roles 1---* users
- datasets 1---* indicators
- datasets 1---* submissions
- reporting_periods 1---* submissions
- users 1---* submissions (owner)
- submissions 1---* data_values
- indicators 1---* data_values
- submissions 1---* submission_history
- users 1---* submission_history
- submissions 1---* submission_amendments
- users 1---* notifications (recipient)
- users 1---* audit_logs

============================================================
9. CONSTRAINTS
============================================================

- Primary keys on all tables.
- Foreign keys on all relationships (no destructive cascades).
- Unique: roles.name, users.email, datasets.code,
  indicators(dataset_id, code), submissions(dataset_id,
  reporting_period_id) [one submission per Dataset + Period],
  data_values(submission_id, indicator_id).
- NOT NULL on required fields.
- Enums: user status (ACTIVE/INACTIVE), dataset status, indicator
  status, data_type, period status (OPEN/CLOSED), submission status
  (DRAFT/SUBMITTED/UNDER_REVIEW/RETURNED/APPROVED), notification
  status, history action.
- Index on audit_logs(resource_type, resource_id).
