============================================================
STAGE 13 — COMPLETE TESTING & UI/UX REFINEMENT
============================================================

PROJECT:
Hospital Health Data Management, Reporting and Analysis System

============================================================
1. STAGE OBJECTIVE
============================================================

Perform a complete end-to-end testing, quality assurance, and
UI/UX refinement pass across the entire application.

The goal is to ensure that the system behaves as one coherent,
professional hospital health-data management application.

Stage 13 must improve both:

1. Functional correctness
2. User experience and visual consistency

UI/UX is a first-class requirement in this stage and must not be
treated as optional or deferred to Stage 14.

Do not redesign the product scope.

Do not add unrelated features.

Do not implement deployment or production infrastructure.

============================================================
4. END-TO-END WORKFLOW TESTING
============================================================

Test the complete real workflow.

FLOW A — ADMIN CONFIGURATION

Admin:

1. Login.
2. Open Admin Dashboard.
3. Create/inspect dataset.
4. Create/inspect indicators.
5. Create/inspect reporting period.
6. Activate/deactivate configuration where applicable.
7. Verify validation messages.
8. Verify duplicate protection.
9. Verify navigation.

Expected:

Configuration changes must behave correctly and must not
break historical records.

------------------------------------------------------------

FLOW B — DATA ENTRY

Data Entry user:

1. Login.
2. View dashboard/application shell.
3. View available active datasets.
4. Select an OPEN reporting period.
5. Create submission.
6. Enter indicator values.
7. Save draft.
8. Leave page.
9. Return to submission.
10. Confirm saved values remain.
11. Submit.
12. Confirm status changes to SUBMITTED.
13. Confirm submission is no longer editable.
14. Confirm notification/workflow behavior.

------------------------------------------------------------

FLOW C — REPORTING REVIEW

Reporting user:

1. Login.
2. Open Review Queue.
3. Find submitted record.
4. Open review detail.
5. Start review.
6. Inspect submitted values.
7. Approve a valid submission.

Verify:

SUBMITTED
→ UNDER_REVIEW
→ APPROVED

Confirm:

- history
- audit
- notifications
- timestamps
- UI status indicators

------------------------------------------------------------

FLOW D — RETURNED SUBMISSION

Create another submission.

Reporting:

1. Start review.
2. Return submission.
3. Provide mandatory reason.

Data Entry:

1. Receive notification.
2. Open returned submission.
3. See return reason.
4. Correct data.
5. Save.
6. Resubmit.

Verify:

RETURNED
→ SUBMITTED

The original submission remains the same record.

No duplicate submission is created.

------------------------------------------------------------

FLOW E — APPROVED DATA

After approval:

1. Open reports.
2. Open dataset report.
3. Open monthly report.
4. Open indicator report.
5. Open submission status report.
6. Open custom report.
7. Open manager dashboard.
8. Open indicator analysis.

Verify only APPROVED data is used where required.

Missing values must remain missing/null.

Do not silently convert missing values to zero.
