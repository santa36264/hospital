1. IMPLEMENTATION SUMMARY
============================================================

Stage 08 implements the first reporting layer of the system.

Four report types are available to REPORTING and ADMIN users:

A. Dataset Report  — approved indicator values for one dataset + period
B. Monthly Report  — all active datasets with approval status per period
C. Indicator Report — approved value for one specific indicator
D. Submission Status Report — workflow overview for all submissions
E. Report History  — log of report access per user

Key design decisions:
- Only APPROVED submissions are treated as finalized data.
- DRAFT, SUBMITTED, UNDER_REVIEW and RETURNED submissions are
  excluded from Dataset, Monthly, and Indicator Reports.
- All report endpoints are read-only; no submission data is modified.
- Report access is logged in report_history (fire-and-forget).
- All IDs validated server-side; frontend cannot bypass validation.
- All report endpoints require authentication + authorized role.

All Stage 03–07 functionality is preserved unchanged.
No Stage 09+ functionality was implemented.

5. API ENDPOINTS (Stage 08 new)
============================================================

All require authentication (401 if not) and REPORTING or ADMIN
role (403 otherwise).

GET /api/v1/reports/dataset
  Query: dataset_id (required), reporting_period_id (required)
  Returns: { dataset, period, submission|null, indicators[],
             valuesMap{indicatorId: valueRow} }
  422 if params missing. 404 if dataset/period not found.
  submission=null when no APPROVED submission exists.

GET /api/v1/reports/monthly
  Query: reporting_period_id (required)
  Returns: { period, rows[{dataset, approvedSubmission|null}],
             summary{totalDatasets, approved, notApproved} }
  422 if param missing. 404 if period not found.

GET /api/v1/reports/indicator
  Query: dataset_id, indicator_id, reporting_period_id (all required)
  Returns: { dataset, period, indicator, submission|null, value|null }
  422 if any param missing. 404 if any ID not found.
  404 if indicator does not belong to the selected dataset.
  submission=null / value=null when no APPROVED submission exists.

GET /api/v1/reports/submission-status
  Query: dataset_id (opt), reporting_period_id (opt),
         status (opt), search (opt), page (opt), per_page (opt)
  Returns: { data[], meta{page, perPage, total, totalPages} }
  All submission statuses included (not just APPROVED).
  422 if status filter is invalid.
  Default page=1, perPage=50, max perPage=200.

GET /api/v1/reports/history
  Returns: { data[], meta{page, perPage, total, totalPages} }
  Scoped to authenticated user only.
  Ordered by accessed_at DESC.

6. REPORT QUERY RULES
============================================================

1. Dataset, Monthly, and Indicator Reports use ONLY
   submission.status = 'APPROVED' as finalized data.

2. DRAFT, SUBMITTED, UNDER_REVIEW, RETURNED submissions are
   excluded from finalized report data (returned as null).

3. Submission Status Report includes ALL statuses — it is a
   workflow overview, not a finalized data report.

4. Indicator must belong to the selected dataset.
   Cross-dataset indicator queries return 404.

5. All IDs (dataset_id, period_id, indicator_id) are validated
   server-side. Frontend claims are not trusted.

6. Report endpoints are READ-ONLY. No endpoint creates, updates,
   or deletes any submission, data_value, or history record.

7. Report history is recorded fire-and-forget (errors logged but
   never thrown to the client).

7. AUTHORIZATION
============================================================

- Anonymous -> 401 on all /reports/* endpoints
- DATA_ENTRY -> 403 on all /reports/* endpoints
- MANAGER -> 403 on all /reports/* endpoints
- REPORTING -> 200 on all /reports/* endpoints
- ADMIN -> 200 on all /reports/* endpoints
  (Admin needs reporting access for system oversight)

Report history is scoped to the authenticated user's own history
(userId = req.user.id in the service). Users cannot access
another user's report history.

10. PROBLEMS ENCOUNTERED
============================================================

PROBLEM 1: Shared report components file (components/reports/index.js)
used JSX syntax but had a .js extension.

ROOT CAUSE: Vite only processes JSX in .jsx files by default.
The build failed with "JSX syntax is disabled" error.

FIX: Renamed to index.jsx. All 5 report page imports from
'../../../components/reports' resolved automatically via
Vite's directory index resolution (index.jsx is found first).
Build succeeded on next run.
