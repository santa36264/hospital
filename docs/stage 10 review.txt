1. IMPLEMENTATION SUMMARY
============================================================

Stage 10 implements the Dashboard and Data Analysis layer.

Three analytics endpoints are exposed under /api/v1/analytics:

A. /analytics/dashboard  — reporting coverage, dataset status,
   key approved indicator values for a period
B. /analytics/indicator-trend  — multi-period trend data for
   one indicator (chronological, no N+1)
C. /analytics/indicator-comparison  — approved values for one
   indicator across two periods with server-side difference
   calculation (percentage-point for percentages)

MANAGER users now have meaningful access: Dashboard + Indicator
Analysis pages are protected by RequireRole(['MANAGER','REPORTING',
'ADMIN']).

REPORTING users have Dashboard and Indicator Analysis added to
their sidebar in addition to all existing report pages.

Key design decisions:
- APPROVED data only for all analytics.
- DRAFT/SUBMITTED/UNDER_REVIEW/RETURNED excluded.
- Missing/unapproved periods return null — never converted to zero.
- Difference for percentage indicators: A - B in percentage
  points (not percentage growth).
- Chronological ordering enforced by the repository (ORDER BY
  start_date ASC).
- Bulk queries: indicator trend uses one JOIN query for all
  period values (no N+1).
- All analytics endpoints are read-only.
- recharts 3.1.0 used for line charts.
- RequireRole extended to accept an array of allowed roles.

All Stage 03–09 functionality is preserved unchanged.
No Stage 11+ functionality was implemented.

4. ANALYTICS APIs
============================================================

All require authentication (401) and MANAGER, REPORTING, or
ADMIN role (403 otherwise). DATA_ENTRY → 403.

GET /api/v1/analytics/dashboard
  Query: reporting_period_id (opt), dataset_id (opt)
  Returns: { period, dataset|null, coverage, datasetStatus[],
             keyIndicators[] }
  If no period_id: uses latest available period.
  404 if provided IDs not found.
  coverage.coverage = null when no active datasets.

GET /api/v1/analytics/indicator-trend
  Query: dataset_id, indicator_id, start_period_id, end_period_id
  All required (422 if missing).
  Returns: { dataset, indicator, periods[], values[] }
  values[].value = null if no approved submission for that period.
  Periods ordered chronologically regardless of input order.
  404 if indicator not in dataset.

GET /api/v1/analytics/indicator-comparison
  Query: dataset_id, indicator_id, period_a, period_b
  All required (422 if missing).
  Returns: { dataset, indicator, periodA, periodB, difference,
             differenceLabel, isNumericComparison }
  difference = null if either value is missing.
  differenceLabel: "+5.0 pp" for percentage, "+35" for numeric.
  isNumericComparison = false for text/date/yes-no types.

============================================================
5. QUERY ARCHITECTURE
============================================================

Dashboard (3 parallel queries after period resolution):
  getLatestPeriod() if no period supplied
  getCoverageForPeriod(): datasets + approved submissions WHERE IN
  getDatasetStatusForPeriod(): datasets + approved subs JOIN users
  getKeyIndicators(): single JOIN all tables, APPROVED only

Indicator Trend (2 queries after validation):
  Get periods in date range (ORDER BY start_date ASC)
  Bulk-fetch: data_values JOIN submissions WHERE period IN (...)
    AND status = APPROVED AND indicator_id = X
  Build null-value map: periods without entries → null

Indicator Comparison (1 query after validation):
  Bulk-fetch: same as trend but WHERE period IN [A, B] only
  Server calculates difference (never trusts frontend)

No N+1 query patterns introduced.

============================================================
6. APPROVED-DATA RULES
============================================================

1. All analytic values originate from:
   data_values JOIN submissions WHERE submissions.status = 'APPROVED'

2. DRAFT, SUBMITTED, UNDER_REVIEW, RETURNED are excluded.

3. Coverage counts only datasets with APPROVED submissions.

4. Indicator values are null (rendered as N/A) for periods
   with no approved submission.

5. No zero-substitution anywhere.

6. The /analytics/dashboard key indicators section shows no
   entries when a period has no approved data.

============================================================
7. CALCULATION RULES
============================================================

Difference = periodB.value - periodA.value (absolute)

For percentage indicators:
  differenceLabel = "+5.0 pp" or "-3.2 pp"
  (percentage POINTS, not percentage growth)

Example: 76% → 81% = +5.0 pp (NOT "+6.6%")

For numeric/decimal:
  differenceLabel = "+35" or "-12.50"

If either value is null:
  difference = null, differenceLabel = null

============================================================

Features:
  - ResponsiveContainer: resizes with page width
  - connectNulls=false: shows gaps for missing periods
  - Custom tooltip with period label + formatted value
  - Axis labels (period labels on X, value+unit on Y)
  - N/A for missing data points in chart and tooltip

  - Chart not rendered
  - Warning shown: "Chart not available for this type"
  - Table view always shown

  - TrendTable always available as alternative
  - ComparisonCard always has a data table underneath
